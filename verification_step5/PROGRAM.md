# Step 5: auditable ambiguity reduction

This is a pilot and an audit record, not a declaration of contract correctness.
Statuses apply to activities: EXECUTED does not mean a finding was fixed.
Authority: existing invariants outrank implementation behavior. New choices below remain PROPOSED.

## Executive assessment

The release criterion is not agreement between implementations. It is disposition of every material ambiguity, conformance of both implementations to independently justified expectations, and evidence that critical negative cases are detected. Two agreeing implementations can share the same defect.

The executable record is `evidence/ledger.json`. Every entry includes the actual command, working directory and exit code; its linked JSON retains stdout/stderr. `evidence/test-scope.md` and `.json` enumerate every original test's actual assertions, exception assertions, exercised calls, source line and fixture body. They state fixture-local conclusions only.

## Differential design and isolation

EXECUTED pilot: `reference/model.py` uses only the standard library and contains no production/test imports. `primary.py` adapts representation only. `differential.py` sends the same JSON values into separate Python `-I` processes. Corpus expectations are calculated from policy §2/I6 and named taxonomy in failure §1; they are not learned from v1 outputs. Recovery conflict is explicitly proposed. Interpreter isolation suppresses ambient Python paths; it is not an ACL or VM boundary.

BLOCKED independence: this author has inspected v1. A new namespace and subprocess do not erase that exposure. The pilot covers only precedence, eight named classification values for FAILED, and one proposed recovery conflict. It does not implement the six contracts, schemas, persistence, evidence authority, checkpointing, filesystem policy or gateway integration. It does not claim independent reexecution of all original tests.

PROPOSED clean-room protocol:

1. Oracle curator freezes versioned docs/invariants, resolves conflicting clauses in decisions, creates traceability IDs and reviewed expected outcomes before implementation results are visible. Hash the specification, corpus and protocol; require reviewer signoff.
2. Give an unexposed implementer a separate repository/identity containing only that specification, wire protocol and neutral fixtures. Do not give src/, existing tests/support.py, adapter internals, v1 output, audit characterization expectations or source history. Shared code is limited to harness/protocol and implementation-neutral JSON fixtures. Keep the primary adapter out of their package.
3. Record the supplied-file manifest, author exposure declaration, access policy, dependencies and implementation digest. Use a distinct representation/algorithm where practical. Access logs support provenance; an import scan alone does not establish independence.
4. Freeze both implementations before disclosure. Reviewer-owned held-out cases and mutation operators must remain hidden. Run each in a separate environment against identical requests; normalize only declared nondeterminism (allocated IDs/timestamps via fixed clock), never errors, verdicts, costs or stop states.
5. Compare each to the normative oracle AND to each other. Classify: implementation defect, spec conflict, harness defect, environmental drift. Minimize every disagreement; record rule IDs, alternative readings, rationale and approved disposition. A disagreement never updates expectations automatically.
6. Freeze the revised specification and regressions; rerun both after approved changes. Clean-room agreement is evidence of reduced ambiguity, not proof that the prose captures all intended behavior.

PROPOSED protocol expansion: request `{schema_version, case_id, operation, initial_state, events, clock}`; response `{decision, verdict, error_code, state, effects, journal_trace, accounting}`. Every stateful case must run within one adapter process; restarting per event would erase ledger/approval state. Primary adapters may translate exceptions to stable codes but must not implement missing validation. Fail on unknown operations, extra output, timeout, missing cases or malformed response. Distinguish adapter crash from contract refusal.
