# بازبینی نشست جداگانهٔ T002

وضعیت: **approve برای پیاده‌سازی محدود T002؛ رسید موفق و جاری آزمون کامل نیز بررسی شد.**

بازبین، نشست جداگانهٔ `t002_review` است. این گزارش، استقلال امنیتی، شاهد Harness
برای انتشار، یا تأیید اجرای کد ناشناس نیست. کد محصول در این بازبینی تغییر نکرد.

## محدوده و روش

تعریف و پذیرش T002، adapter، آزمون‌های آن، سه قالب اصلی، pin منبع، workflow محدود،
راهنمای انتخاب و آزمایش native بررسی شدند. رفتار ProjectBook و بخش مرتبط engine،
gate، shell و resume از منبع owning پین‌شده خوانده شد.

علاوه بر خواندن کد، یک probe مستقل در پوشهٔ موقت یکتا با assertion اجرا شد؛ خروج
فرایند صفر بود. probe، ۱۱ هش منبع upstream و ۴ فایل vendor را تطبیق داد، سپس
حفظ REQ/ADR فارسی و چندخطی، تکرار پس از بازگشایی، بی‌اختیاری ادعای PASS و رد نسخهٔ
قدیمی را مشاهده کرد. پوشهٔ probe پس از پایان پاک شد. این مشاهدهٔ بازبین جای رسید
کنترل‌کنندهٔ آزمون اصلی را نمی‌گیرد.

رسید `docs/progress/T002-native-receipt.json` نیز بررسی شد: خروج واقعی صفر، بدون
timeout یا overflow، مدت اجرای فرایند ۱۴٫۹۵۳ ثانیه، و source/after digest برابر
`8abbe1646df4a7cd030f5e0926f284eeee75f641ab8d0f1dc3716a3f7548c901` است.
نسخهٔ بررسی‌شده Spec Kit برابر `1.4.1.dev0` از commit
`2ee2b1e8005905db05f5717300a469b3068b908f` است؛ این نام، ادعای release پایدار نیست.

## ارزیابی پذیرش

۱. **رفت‌وبرگشت نیاز و شناسه:** `export_bundle` در `src/csef_gate/integrations/spec_kit.py:27`
نسخهٔ کامل owner snapshot را کنار Markdown ذخیره می‌کند. `read_bundle` دادهٔ دقیق را
برمی‌گرداند و import نسخهٔ پذیرفته‌شده را با نسخهٔ جاری داخل تراکنش مقایسه می‌کند.
شناسهٔ نیاز یا ADR از FR/T تولیدشده دوباره حدس زده نمی‌شود. این یک envelope همراه
اسناد است، نه parser عمومی تمام Markdownهای دلخواه Spec Kit؛ این محدودیت صریح است.

۲. **مرز اختیار:** تنها write اتصال، یک ردیف `changes` با وضعیت `proposed` است
(`spec_kit.py:106`). هیچ مسیر finish، amend یا Gate در adapter وجود ندارد. دادهٔ
اسناد اجرا نمی‌شود. آزمون native نشان داد approve می‌تواند workflow بومی را تمام
کند، در حالی که هدف، facts، تمام وضعیت‌های stage و release CSEF دست‌نخورده می‌مانند.

۳. **بازیابی:** `BEGIN IMMEDIATE` در `spec_kit.py:93` کنترل نسخه و dedupe محتوای
پیشنهاد را هم‌زمان پوشش می‌دهد. lookup در `spec_kit.py:101` مانع ثبت تکراری همان
ورودی می‌شود. آزمایش native واقعاً import را پس از قطع بین commit و ثبت نتیجهٔ
مرحله دوباره اجرا کرده و `replayed=true` و شمار ثابت پیشنهاد مشاهده شده است.
ادامهٔ بدون رأی در حالت paused باقی مانده است. دادهٔ عوض‌شده پیشنهاد تازه است و
پیشنهاد قبلی را بازنویسی نمی‌کند. عملیات خارجی عمومی در این نمونه وجود ندارد؛
بنابراین ادعای exactly-once عمومی از این نتیجه مجاز نیست.

۴. **تصمیم استفاده:** استفاده از قالب و فرایند سندمحور و نگهداری اختیار در
ProjectBook/Gate موجود، با نتیجهٔ محدود آزمایش و کد owning سازگار است. native
resolver نیز حفظ override پروژه را واقعاً سنجیده است. کنارگذاشتن engine به‌عنوان
مرجع اختیار، به معنای ساخت orchestrator جایگزین در این تغییر نیست.

## یافته‌ها و اصلاح بررسی‌شده

ایراد مسدودکنندهٔ P1/P2 در محدودهٔ این تغییر پیدا نشد.

در تلاش نخست native، assertion آزمایش انتظار `failed` برای رد gate داشت؛ وضعیت
واقعی `aborted` بود. state ذخیره‌شده و owning source در
`src/specify_cli/workflows/_execution.py:822` این معنا را تأیید می‌کنند. اصلاح فقط
انتظار آزمایش به معنای واقعی `on_reject=abort` است؛ پذیرش ضعیف نشده است. رسید
شکست با نام `T002-native-attempt1.json` حفظ و رسید اصلاح‌شده موفق شده است.

## محدودیت‌های باقی‌مانده

- binding به مسیر ProjectBook وابسته است؛ جابه‌جایی کتاب نیازمند export تازه است.
  هش مسیر، امضا یا دفاع در برابر نویسندهٔ محلی نیست.
- فقط ثبت پیشنهاد محلی تکرارپذیر پشتیبانی می‌شود. نتیجهٔ نامعلوم عملیات خارجی
  نباید با این adapter کورکورانه retry شود.
- قطع با KeyboardInterrupt پنجرهٔ گم‌شدن نتیجه را می‌سنجد؛ power loss و خرابی
  storage یا محیط خصمانه سنجیده نشده‌اند.
- کیفیت معنایی طرح‌های تولیدشده، سازگاری فراخوانی تمام عامل‌ها، هزینهٔ مدل و بهبود
  پروژهٔ پیشرفته اندازه‌گیری نشده‌اند. گردش‌کار native این آزمایش، model call ندارد.
- مرز loopback ویندوز و شروط مستقل انتشار تغییر نکرده‌اند.
