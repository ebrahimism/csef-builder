# T007 — مسیر مشترک گفتگو، نقش‌ها، ساخت و تحویل

Workflow سرویس مشترک گفتگو و CLI است؛ خودِ مسیر نمونهٔ تاریخی import نشده است.
پرونده، نسخه‌های نیاز، سؤال، بودجه و lease موجود دوباره استفاده می‌شوند. نخستین
مرحلهٔ آماده انتخاب می‌شود و مرحلهٔ وابسته، پیش از شروع، تحویل‌های قبلی را از
نظر نسخه و بایت artifact بررسی می‌کند. ادعای complete نیز artifact نهایی را
دوباره می‌سنجد. pipeline شش تا ۲۴ مرحله دارد: سه جایگاه نخست مدارک نقش‌ها و
جایگاه‌های بعدی برش‌های اجرایی‌اند؛ مدل اجازهٔ تغییر pipeline یا Gate ندارد.

پیش از هر تماس، سؤال‌های باز برمی‌گردند. API پاسخ همان Questions است و CLI
project answer باقی می‌ماند. ساخت مدارک از assist موجود استفاده می‌کند؛ مدارک
خالی، مسیر تکراری، شناسه‌های پوشش‌نداده و مسئلهٔ حل‌نشده تحویل معتبر نمی‌سازند.
این‌ها بررسی ساختاری‌اند، نه اثبات معماری. دو جایگاه معماری و قرارداد نشست
بازبینی لازم دارند. needs_owner سؤال پایدار می‌سازد؛ تکرار سؤال معلوم دوباره
انتظار بی‌پاسخ ایجاد نمی‌کند. رد بازبین، مرحلهٔ وابسته را مسدود نگه می‌دارد.

کد در Gate موجود و همان مخزن مشترک ارزیابی می‌شود. oracle پیش از فراخوانی عامل
attach و منجمد است. ارزیابی شکست‌خورده به عامل با زمینهٔ owner و شاهد واقعی
بازگردانده می‌شود؛ تلاش قبل از تماس در بودجهٔ run و بودجهٔ کلی پروژه ثبت می‌شود.
ادامهٔ شکستِ معلوم همان run و candidate و سقف تلاش را نگه می‌دارد. خروج/قطع
نامعلوم، lease را آزاد نمی‌کند و بازیابی صریح قبلی لازم است.

تحویل اجرایی از بایت snapshot همان evaluation ساخته می‌شود. اعتبارسنجی قدیمی
accept به helper داخلی مشترک _verified_in استخراج شده است؛ گزارش/hash، source،
spec، موردهای آزمون، boundary، measurement_only و tuple نسخه/hash صاحب پروژه
همچنان بررسی می‌شوند. Book.finish پس از آماده‌سازی blob و داخل writer transaction
نهایی، callback داخلی controller را اجرا می‌کند؛ callback دوباره evaluation را
از DB resolve و به بایت artifact بسته می‌کند. JSON یا permit مدل جای آن نیست.
آماده‌سازی ArtifactStore خارج lock است تا اتصال نویسندهٔ تو در تو ساخته نشود.

مرحلهٔ بعد بایت snapshot معتبر قبلی را carry-forward می‌کند. کد candidate تازه
دوباره Gate می‌گیرد؛ ادعای بازبین یا مدل، اجرا را PASS نمی‌کند. REVIEW، از جمله
measure-only ویندوز، خروجی قابل مشاهده نگه می‌دارد اما dependent را جلو نمی‌برد.
این engine هرگز accept یا mint checkpoint را صدا نمی‌زند. تنها مسیر قدیمی و
مستقل Gate.accept اختیار checkpoint خود را با همان شروط پیشین حفظ کرده است.

CLI تازه workflow init/status/attach/continue را به همین سرویس وصل می‌کند؛ تا
intake کامل نشده نصب یا تماس مدل لازم نیست. ادامهٔ زنده از adapter فعلی Codex
استفاده می‌کند، اما هنگام ساخت این برش هیچ تماس provider زنده یا پولی اجرا نشده.
این CLI هنوز UI مستقل یا تضمین کاهش زمان کاربر نیست.

آزمون پذیرش مسیر مثبت، از گفتگوی ناقص شروع می‌کند، چهار پاسخ را از API می‌دهد،
هفت تحویل می‌سازد و یک برنامهٔ واقعی جمع عدد/خطای ورودی را در subprocess اجرا
می‌کند. model replies از fixture و probe نیز TEST DOUBLE صریح‌اند؛ عبور این
آزمون، موفقیت مدل زنده یا مرز امنیت OS نیست. هیچ SQL برای جلو بردن وضعیت در
مسیر مثبت نوشته نمی‌شود. آزمون‌های منفی review/مدرک نامعتبر، REVIEW، تغییر owner
یا proposal بین خواندن اولیه و commit، بودجهٔ resume و خرابی artifact را می‌سنجند.

حدود: یک oracle اجرایی ثابت برای این برش وجود دارد؛ معیار متفاوت برای هر مرحله
یا تولید/کفایت معنایی oracle پیاده نشده است. عبور برش‌های بعد با همین معیار به
معنی پیاده‌شدن قابلیت جدید نیست. پشتیبانی زبان/پروژهٔ پیشرفته، benchmark عمومی،
صرفه‌جویی دلاری، auth انسان و ایزولاسیون عمومی از این کار نتیجه نمی‌شوند. شواهد
focused/full و مرور جداگانهٔ منبع نهایی، شرط اتمام هستند؛ این سند شاهد اتمام نیست.
