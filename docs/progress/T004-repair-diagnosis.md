# سابقهٔ بررسی T004

اجرای متمرکز اولیه (`261b91f937bf45088c688f45ff9c360c`) موفق بود؛ رسید در
`T004-focused-initial.json` حفظ شد. بازبینی جدا سپس حالت‌های lifecycle تکمیلی را
مشخص کرد: fencing به‌تنهایی توقف worker نیست؛ seq دو journal محلی با هم برخورد
می‌کند؛ restore باید مالکیت تاریخی runtime را باطل کند. این موارد در کد و
آزمون اضافه شدند، بدون کاهش پذیرش یا تغییر آزمون‌های قبلی.

اجرای گستردهٔ متمرکز (`20377e53f4cd453a88e7eff689fc6189`) شامل ۴۷ مورد بود:
۴۶ موفق و یک شکست، بدون skip یا error. رسید در `T004-focused-attempt2.json`
حفظ شد. شکست از suspend بود که پس از ثبت سؤال adaptive دوباره packet می‌ساخت؛
packet به‌درستی به‌علت سؤال بی‌پاسخ متوقف می‌شد. suspend اکنون زیر یک تراکنش،
lease و stage.packet_hash/version جاری را مستقیم کنترل و draft-only/outcome/release
را با هم ثبت می‌کند. آزمونِ جلوگیری از فراخوانی دوبارهٔ مدل تا پاسخ صاحب پروژه
تغییر نکرده است. بررسی محدود بعدی و full-suite باید این اصلاح را تأیید کنند.

دو حالت جدید نیز سنجیده می‌شوند: draft واقعاً برگشته می‌تواند مالکیت را بدون
handoff آزاد کند، اما نتیجهٔ نامعلوم فراهم‌کننده اجازهٔ فراخوانی دوم خودکار نمی‌دهد.

مقصد GitHub همان URL صاحب پروژه است. اتصال ابزار push=false گزارش کرد و آزمون
محلی `git push --dry-run` بدون تعامل و بدون ارسال فایل نیز با 403 برای حساب
`ebrahimism` رد شد. حساب، ورود یا visibility تغییر نکرد؛ توسعهٔ محلی ادامه می‌یابد.
