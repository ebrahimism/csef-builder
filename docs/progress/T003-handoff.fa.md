# تحویل محدود T003 — پایگاه کنترل و مهاجرت

پوشهٔ کار: `F:\cffmam`. ادامهٔ کار فعال T003 از روی وضعیت موجود؛ فایل‌های
نامرتبط، از جمله `golden_gate_bridge.pptx`، دست‌نخورده باقی ماندند. تعریف backlog،
REQ-104 و REQ-106 و تصمیم‌های پذیرفته‌شده تغییر نکردند.

## رفتار قابل مشاهده

- ساخت پرونده یا Gate تازه از `control.sqlite3` نسخهٔ ۱ استفاده می‌کند؛
  `attach=True` امکان اتصال جزء دوم به همان پایگاه را می‌دهد. مخزن‌های منطقی
  ProjectBook و Gate حفظ شده‌اند و `ControlStore.transaction()` تراکنش مشترک دارد.
- مخزن‌های قدیمی همچنان خوانده می‌شوند. مهاجرت فقط با انتخاب صریح دو ریشه، مقصد
  جدا و جدید، و حالت offline انجام می‌شود. دادهٔ قدیمی درجا ارتقا یا حذف نمی‌شود.
- نسخه‌های هدف، facts، handoff، پیشنهادها، تماس‌ها، اجراها و شواهد کپی می‌شوند.
  پشتیبان SQLite شامل تغییرات commit‌شدهٔ WAL است. هش فایل‌ها پیش و پس از کپی
  بررسی می‌شود. جدول یا ستون ناشناخته، trigger، collision و دادهٔ orphan پذیرفته نمی‌شوند.
- تکرار همان انتقال بدون تغییر، `unchanged` می‌دهد. تغییر منبع یا مقصد باعث توقف
  می‌شود. خروجی ناقص به مقصد نهایی منتقل نمی‌شود؛ staging ناموفق برای بررسی می‌ماند.
- بازیابی، دو کپی جدید از پشتیبان می‌سازد؛ روی دادهٔ زنده چیزی نمی‌نویسد. تغییرات
  بعدی پروندهٔ یکپارچه مانع بازیابی نسخهٔ پیش از انتقال نیست.
- گزارش‌های واردشده تاریخی‌اند. evaluations به stale می‌روند، اجراهای ناتمام
  migration_review می‌شوند و پذیرفته‌های قبلی قابل تغییر نیستند. پذیرش تازه به
  اجرای تازهٔ Gate نیاز دارد. نسخهٔ بازیابی‌شده نیز همین محدودیت را دارد.
- چهار قرارداد نسخه‌دار و schema همراه، فیلد ناشناخته را رد می‌کنند. اعتبارسنجی
  شکل گزارش به‌تنهایی منشأ معتبر یا مجوز انتشار نیست.

## اصلاحات این ادامه

مسیرها پس از رد symlink/junction و پیش از کنترل جدابودن، canonical می‌شوند؛
مسیر دارای `..` دیگر نمی‌تواند مقصد را داخل منبع قرار دهد. همین بررسی برای اتصال
Gate به پرونده نیز اعمال شد. manifest انتقال/بازیابی پیش از ایجاد staging از نظر
نسخهٔ صحیح integer، شکل، ریشه، پایگاه مجاز، جدول‌ها، fingerprint و فهرست کامل
فایل‌های پشتیبان بررسی می‌شود. نسخهٔ boolean/float و manifest ناقص رد می‌شود.

اصلاحات قبلی قفل فایل و بستن اتصال SQLite در ویندوز حفظ شده‌اند؛ نام staging کوتاه
است و مقصدهای بیش از حد طولانی پیش از کپی رد می‌شوند. سابقهٔ شکست قبلی در
`T003-focused-attempt1.json` و تشخیص در `T003-repair-diagnosis.md` باقی است.

## شواهد پذیرش

`tests/persistence/test_migrations.py` حفظ بایت‌های منبع و وضعیت پرونده، خواندن
handoff پس از انتقال، schema قدیمی واقعی، تکرارپذیری، بازگشت پس از اصلاح دادهٔ
زنده، rollback تراکنش مشترک، اتصال هم‌زمان، WAL، خرابی ذخیره‌سازی، دستکاری پشتیبان،
checkpoint تاریخی و رد PASS نامعتبر را می‌سنجد. سه آزمون جدید، مسیرهای مستعار،
اتصال داخل پوشهٔ کنترل و manifest خراب را پیش از نوشتن بررسی می‌کنند.

آزمون‌های Gate از `UNIT_TEST_FAKE` استفاده می‌کنند؛ این شاهد جداسازی امنیتی محیط
یا موفقیت اجرای واقعی ناشناس نیست. `T003-schema-check.json` تطابق چهار schema با
مدل‌های اجرایی را ثبت می‌کند. آزمون متمرکز: ۲۳ موفق؛ کل مخزن: ۱۷۶ موفق؛ بدون
شکست، خطا، skip یا timeout. رسید کامل `0403dee228c146b8a66e938fb0cca5ca` در
`T003-full-check.json` ثبت شد؛ هش منبع پیش و پس از اجرا یکسان است و با آزمون
متمرکز تطبیق دارد. تصمیم نشست جدا در `T003-independent-review.md` ثبت می‌شود.

## روش استفاده و بازیابی

پس از توقف همهٔ نویسنده‌های دو مخزن، در محیط Python پروژه:

```text
python -m csef_gate.persistence.migrations preflight --project BOOK --gate GATE --destination NEW
python -m csef_gate.persistence.migrations migrate --project BOOK --gate GATE --destination NEW --offline
python -m csef_gate.persistence.migrations restore-copy --store NEW --destination RESTORED
```

`BOOK` و `GATE` باید متعلق به یک پروژه و صریحاً انتخاب شده باشند؛ این ارتباط از
نام پوشه حدس زده نمی‌شود. `NEW` و `RESTORED` مسیرهای جدا و جدیدند. فایل‌های منبع
را تا بررسی نسخهٔ منتقل‌شده نگه دارید. برای بازیابی، پشتیبان و manifest باید با هم
حفظ شوند. قفل باقی‌مانده پس از crash نیازمند بررسی نبود نویسندهٔ فعال است؛ ابزار
قفل را خودکار حذف نمی‌کند. شکست انتقال ممکن است staging نگه دارد.

## محدودیت‌ها

- این کار فقط برش T003 است؛ سرویس عمومی پروژه، UI و همهٔ ۳۸ کار ساخته نشده‌اند.
- اجرای انتقال offline است؛ قفل SQLite جای توقف نویسندگان فایل را نمی‌گیرد.
  پایگاه محلی و manifest قابل نوشتن توسط مالک، مرز امنیتی در برابر همان مالک نیستند.
- فایل‌های باقی‌مانده از قطع اتصال `Gate.initialize(..., attach=True)` خودکار پاک
  نمی‌شوند. تراکنش DB برمی‌گردد و تلاش بعدی با حفظ فایل‌ها متوقف می‌شود؛ بررسی و
  بازیابی دستی لازم است. این با بازیابی نسخهٔ مهاجرت‌شده متفاوت است.
- manifestهای شناخته‌شدهٔ نسخهٔ ۱ پشتیبانی می‌شوند؛ نسخهٔ آینده به مهاجرت تازه نیاز دارد.
- مانع loopback بومی ویندوز حل نشده؛ measure-only همچنان REVIEW است. این تغییر
  هیچ checkpoint انتشار، push، استقرار یا تماس پولی بیرونی ایجاد نمی‌کند.
- بازبینی در یک نشست جدا از همین محیط انجام شده؛ هزینهٔ توکن/دلار گزارش نشده و
  ادعایی دربارهٔ کاهش هزینه یا موفقیت پروژهٔ پیشرفته نداریم.
