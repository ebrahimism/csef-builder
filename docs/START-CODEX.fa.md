# شروع ساخت CSEF با Codex

این بسته برای ساخت خود CSEF از روی نقشهٔ راه است. عامل اجرایی همان Codex است؛
کنترل‌کنندهٔ کوچک فقط پیشرفت، وابستگی‌ها، آزمون واقعی و مدرک اتمام را ثبت می‌کند.
این بسته محصول نهایی CSEF یا مجوز انتشار نیست.

## شروع ساده

پروژهٔ `F:\cffmam` را در Codex باز کنید. پس از نصب افزونه، یک گفتگوی تازه در همین
پروژه باز کنید تا مهارت شناسایی شود. متن آماده در
`docs/progress/START-PROMPT.txt` قرار دارد. اگر افزونه در فهرست دیده نشد، Codex
می‌تواند همان دستورالعمل داخل مخزن را بخواند؛ نصب افزونه شرط اجرای کنترل‌کننده نیست.

## فرمان‌های محلی

از ریشهٔ پروژه، با Python 3.11 یا بالاتر و وابستگی‌های فعلی:

```powershell
python tools/csef_backlog.py next
python tools/csef_backlog.py packet T001
python tools/csef_backlog.py start T001
python tools/csef_backlog.py check T001
python tools/csef_backlog.py complete T001 --review docs/progress/T001-review.json
```

مهارت، قالب گزارش پذیرش را دارد. ابتدا مدرک واقعی را بسازید، سپس آزمون کامل را
اجرا کنید. نتیجهٔ آزمون قبل از آخرین تغییر کد برای اتمام پذیرفته نمی‌شود. آزمون‌های
شکست‌خورده، خالی یا دارای مورد ردشده/اجرانشده، رسید موفق نمی‌گیرند. داوری معنایی
دربارهٔ پذیرش همچنان وظیفهٔ عامل و بازبین است؛ فایل گزارش به‌تنهایی صحت ادعا را ثابت نمی‌کند.

برای توقف و ادامهٔ قابل پیگیری:

```powershell
python tools/csef_backlog.py block T001 --reason 'علت مشخص توقف'
python tools/csef_backlog.py history
python tools/csef_backlog.py resume T001
```

## ساخت و نصب بسته

```powershell
python tools/package_csef_builder.py
codex plugin marketplace add F:/cffmam/deliverables/csef-local --json
codex plugin add csef-builder@csef-local --json
codex plugin list --json
```

نسخهٔ نصب‌شده کپی بسته است. تغییرات را در `plugins/csef-builder` اعمال کنید و
پس از افزایش نسخه، بسته را دوباره بسازید و از مسیر رسمی به‌روز کنید؛ کش نصب را ویرایش نکنید.
برای ثبت منبع و نصب، Codex به محل تنظیمات خودش دسترسی نوشتن نیاز دارد.
فرایند نصب تنظیمات دیگر را با فایل آماده جایگزین نمی‌کند.

## محدودهٔ اولین اجرا

T001 خط مبنا و وضعیت Git را تثبیت می‌کند. T002 استفادهٔ مجدد از Spec Kit را با
نمونه و تصمیم مستند می‌سنجد. تا بسته‌شدن واقعی T001، T002 شروع نمی‌شود. این شروع
مجوز اجرای بی‌وقفهٔ همهٔ ۳۸ کار یا ساخت همهٔ ماژول‌های پیشنهادی نیست.
آغاز Git و ثبت نسخه را با حفظ فایل‌ها و هویت موجود انجام دهید؛ هویت یا مخزن راه دور
نسازید. وابستگی بیرونی را بدون آزمون صرفاً به‌خاطر حضور در فهرست اتصال‌ها نپذیرید.

برای تصمیم‌های معماری، قرارداد، امنیت و مهاجرت، گزارش یک نشست جدا لازم است.
این گزارش به‌معنی تضمین مدل مستقل یا امنیت اجرا نیست. مرز فعلی loopback ویندوز
همچنان حل‌نشده است و حالت سنجش نباید به انتشار تبدیل شود.
