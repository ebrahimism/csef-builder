# محدودهٔ استفاده از Spec Kit در CSEF

این مسیر راهنمای انتخاب قالب است؛ بستهٔ قابل‌نصب preset یا افزونهٔ محصول نهایی نیست.
نسخهٔ مرجع در `../upstream.json` با commit و هش فایل‌ها ثبت شده است. سه قالب و
مجوز MIT، بدون تغییر در `../upstream/` نگهداری می‌شوند. کد اجرایی Spec Kit وارد
وابستگی هستهٔ CSEF نشده است؛ نصب آزمایشی فقط در `.csef-build/` قرار دارد.

قالب‌های spec/plan/tasks برای تبادل اسناد پذیرفته می‌شوند. متن قالب منتخب، از جمله
override صریح پروژه، حفظ می‌شود. صادرکننده پوشهٔ تازه می‌خواهد و فایل موجود را
جایگزین نمی‌کند. در نمونهٔ واقعی، انتخاب override توسط `PresetResolver` خود Spec Kit
آزمایش می‌شود. adapter مستقل ترتیب اولویت قالب‌ها را دوباره پیاده نمی‌کند.

## قرارداد تبادل محدود

- `csef.json` نسخه، هش، هدف، پاسخ‌ها، تمام شناسه‌ها و متن دقیق واقعیت‌های صاحب پروژه
  را نگه می‌دارد؛ spec/plan/tasks متن پیشنهادی‌اند. شناسهٔ نیاز از شمارندهٔ FR یا T
  بازسازی نمی‌شود و متن چندخطی یا فارسی از بین نمی‌رود.
- ورود فقط به شکل یک پیشنهاد در ProjectBook موجود ثبت می‌شود. هیچ فراخوانی
  `finish`، اصلاح هدف، پذیرش Gate، اجرای متن اسناد یا اثر خارجی در این adapter نیست.
- تکرار ورودی دقیق، حتی پس از گم‌شدن پاسخ و بازشدن دوبارهٔ برنامه، همان پیشنهاد را
  برمی‌گرداند. تراکنش واحد، کنترل نسخه و حذف ثبت تکراری را با هم انجام می‌دهد.
  متن تغییرکرده پیشنهاد تازه است؛ پیشنهاد قبلی بازنویسی نمی‌شود.
- تغییر شناسه، متن پذیرفته‌شده، نسخه یا پروژهٔ مقصد، ورود را متوقف می‌کند. تغییر هدف
  باید از مسیر اصلاح صریح صاحب پروژه انجام شود و سپس خروجی تازه گرفته شود.
- binding این نمونه به مسیر ProjectBook است؛ انتقال کتاب پروژه به مسیر دیگر نیازمند
  export تازه است. این binding و هش، امضا یا محافظت در برابر نویسندهٔ محلی نیستند.

قالب tasks بالادستی آزمون را اختیاری می‌داند. در خروجی CSEF صریحاً ثبت می‌شود که
قبولی کارهای مشمول آزمون به بررسی واقعی کنترل‌کننده نیاز دارد. تیک tasks، واژهٔ PASS
و approve در Spec Kit به‌تنهایی نه شاهدند و نه اختیار پذیرش دارند. محل ابهام مؤثر
باید برای تصمیم صاحب پروژه متوقف بماند؛ بخش Assumptions قالب مجوز حدس دربارهٔ هدف نیست.

## اجرای نمونهٔ محدود

از ریشهٔ CSEF و با `src` در مسیر Python:

```powershell
$env:PYTHONPATH = (Resolve-Path src).Path
python -m csef_gate.integrations.spec_kit export --book PATH_TO_BOOK --bundle NEW_DIRECTORY --templates integrations/spec-kit/upstream
python -m csef_gate.integrations.spec_kit import --book PATH_TO_BOOK --bundle NEW_DIRECTORY
```

این فرمان‌ها برای استفادهٔ مهندسی‌اند؛ رابط عادی کاربر نباید او را درگیر JSON یا
انتخاب قالب کند. نمونهٔ `../workflows/csef-review.yml` فقط در پروژهٔ آزمایشیِ تازه
با دو مسیر ثابت `book` و `exchange` اجرا می‌شود. shell آن ثابت و بررسی‌شده است؛
ورودی پویا داخل متن shell قرار نمی‌گیرد. از آن برای اجرای workflow دلخواه استفاده نکنید.

`experiments/spec_kit/run.py` با نسخهٔ واقعی Spec Kit، توقف، ادامهٔ بدون رأی، approve
جعلی، رد، و قطع پس از ثبت پیشنهاد و پیش از ثبت نتیجهٔ مرحله را آزمایش می‌کند.
در این گردش‌کار هیچ عامل مدل، انتشار یا سرویس خارجی فراخوانی نمی‌شود.

## تصمیم محدود استفاده

انتخاب: استفاده از قالب‌ها و فرایند سندمحور، همراه با adapter پیشنهاد در ProjectBook.
موتور workflow به‌عنوان منبع اختیار CSEF انتخاب نمی‌شود. اسناد رسمی بالادستی خود
توضیح می‌دهند که اثر ثبت‌نشده ممکن است در resume تکرار شود و shell با دسترسی کاربر
اجرا می‌شود. بنابراین این نمونه فقط اثر محلیِ مشخص و تکرارپذیر را پشتیبانی می‌کند؛
عملیات خارجی با نتیجهٔ نامعلوم نیازمند رسیدگی جداست.

این ارزیابی، مقایسهٔ هزینه یا کیفیت خروجی مدل نیست. صرفه‌جویی، برتری عمومی، امنیت
اجرای کد ناشناس یا آمادگی انتشار از آن نتیجه نمی‌شود. محدودیت loopback ویندوز پابرجاست.
